# route_connectivity — прямые пробы адресов узла

`route_connectivity_probe_node(instance, group, nq)` берёт общую запись узла из
registry и запускает асинхронные пробы. Собственный узел, пир в SLEEP-фазе и уже
идущие/отложенные пробы пропускаются. NAT-окно сохраняет незнакомые IP для проверки
входящих; Android standby откладывает старт до активного интервала.

Для каждого семейства перебираются до 16 уникальных IP:port. Нулевые адреса/порты
пропускаются. Дедупликация выполняется по IP:port, без учёта типа адреса/протокола.

UDP проверяется с обычных локальных сокетов того же семейства (до 8).
IPv4-кандидаты фильтруются через `sock_match` в порядке списка сокетов; предпочтений
по /24 или рейтинга DIRECT/EIM здесь нет. Для IPv6 сначала идут сокеты той же /64,
затем остальные IPv6. TCP-сокеты и `probe_only` для UDP исключены.
С каждого UDP-сокета идёт последовательная серия из `CONN_PROBE_COUNT=3` ping;
достаточно одного ответа в серии, чтобы завершить этот адрес успешно. Следующий
сокет пробуется, если текущая серия не дала успеха. RTT — минимум успешной серии,
а не обязательный минимум по всем доступным сокетам.

TCP-адрес проверяется одним `etcp_send_tcp_ping` через STCP-клиент, независимо
от набора UDP-сокетов. Используются REALITY-параметры из записи узла; адрес с
REALITY-флагом без параметров пропускается. Проба не создаёт READY-сессию группы.
Таймаут по умолчанию 1000 мс; `route_connectivity_set_probe_timeout_ms(ms)` меняет
его для новых контекстов всего процесса, 0 игнорируется.

Результаты находятся в `nq->connectivity`: `probe_status`, `pending_count`,
`interface/nat/real_status`, соответствующие `*_min_rtt` и `*_probe_time`.
RTT и время — timebase (0.1 мс), UINT16_MAX означает неизвестный RTT.
INTERFACE обновляет также исторические поля REAL; отдельного третьего адреса
для этого не требуется. Успех одного адреса не затирается неудачей другого.
Завершение последней pending-пробы устанавливает DONE, обновляет БД и вызывает
`topo_fire_nodeinfo_cbk`. Если пригодных адресов/сокетов нет, DONE означает только
конец обхода: UNKNOWN не превращается автоматически в UNREACHABLE.

`route_connectivity_cancel_node(nq)` отменяет все UDP/TCP-пробы и отложенный старт,
освобождает контексты и сбрасывает probe_status/pending_count. Последние результаты
RTT/status сохраняются. Отмена нужна до удаления узла, группы или рабочих сокетов.
`route_connectivity_cancel_all(instance)` обходит все группы, не только UTUN.
Все вызовы выполняются в потоке ядра; group/nq заимствованы до завершения или отмены.

`route_ping` также выполняет прямые UDP-пробы, но для измерения наблюдаемого endpoint;
выбор наблюдателей/помощников и вычисление NAT-профиля находятся в `nat_detection`.
