# topo_node — модель, снимок и локальное состояние узла

## Два уровня записи

TOPO_NODE содержит общую идентичность: node_id, диагностический ver, timestamp, ключи,
Ed25519-подпись, имя, тип/активность, списки SOCKMETA4/ADDR4/SOCKMETA6/ADDR6/REALITY.
Групповых flags, group_id, подсетей и путей в нём нет.

TOPO_GROUP_NODE содержит node_id, подсети, пути, last_ver/last_timestamp, состояние conn_mgr,
пробы связности, presence/up, radio/phone_status и заимствованный NCD handle.
Удалённые записи находятся в group->nodes; локальная запись хранится отдельно в group->local_node.
TOPO_NODEPATH содержит заимствованный ETCP_CONN, hop_count, cumulative_rtt, exchange
и массив uint64_t[hop_count] непосредственно после структуры.

Все операции выполняются в uasync-потоке ядра. BGP-сессией/обменом управляет topo_group,
хранением в общей SQLite — topo_node_sqlite. Этот модуль также готовит локальную запись,
обновляет адреса и инициирует рассылку после их изменения.

## Реестр и память

node_registry хранит отдельный ll_entry с node_id и указателем TOPO_NODE.
registry_find возвращает заимствованный указатель. Для удержания записи берётся registry_ref;
последний registry_unref удаляет registry entry, списки, имя и сам объект.

registry_store принимает входной объект при успехе и возвращает запись с одной новой ссылкой:

- Более свежий подписанный timestamp заменяет всю запись, включая пустые списки, но адрес существующего объекта сохраняется.
- Старый/равный вход освобождается, возвращается прежняя запись. Конфликт одинаковых timestamp логируется.
- Для двух bootstrap-записей с timestamp=0 сливаются присутствующие списки; полноценная идентичность может обновить скалярные поля.
- При новой регистрации более свежий/равный сохранённый снимок SQLite может заменить вход.
- При NULL-результате вход остаётся у вызывающего.

У зарегистрированной записи используется registry_unref. Незарегистрированный результат parser/SQL
уничтожается topo_node_destroy(groups, ni). Списки сокетов/адресов/подсетей принадлежат пулам groups,
имя, REALITY, контейнер подсетей и отдельно возвращённый hop-list — u_malloc/u_calloc.
Для освобождения pooled-списков нужен тот же контейнер groups.

topo_nodeq_free_group_fields снимает ссылку реестра, освобождает подсети и обнуляет handle;
сам nq и пути остаются. topo_nodeq_clear_paths освобождает пути/контейнер, транспорт не закрывает.
Удалённый узел удаляется через topo_nodeq_remove_node: отмена проб, удаление IPv4-маршрутов,
удаление из очереди и освобождение полей/записи. local_node освобождает владелец группы отдельно.

## Timestamp и подпись

timestamp — Unix microseconds, версия всей подписанной записи; 0 обозначает bootstrap.
ver — циклический счётчик 1..255, не фильтр свежести. Групповой last_timestamp хранит последнюю
принятую версию в этой группе, last_ver используется для диагностики.

topo_node_build_sig_msg создаёт канонические байты в таком порядке:

| Поле/секция | Представление подписи |
| --- | --- |
| node_id, ver | uint64 в нативном порядке, затем байт ver |
| timestamp | 8 байт BE |
| public_key | X25519, 32 байта |
| node_name | До 63 байт и NUL |
| client_type, client_activity | По одному байту |
| Счётчики | По байту: v4 sockets, v4 addrs, v6 sockets, v6 addrs, REALITY |
| SOCKMETA4, ADDR4, SOCKMETA6, ADDR6 | Полные списки в текущем порядке; адреса сетевыми байтами, порты LE |
| REALITY | socket_id, short_id[8], server_pubkey[32], version[3], SNI с NUL |

SOCKMETA содержит id/config_type/mapping/inbound/source, каждый по байту.
Групповые flags/id, подсети, hops и cumulative_rtt не входят в подпись.
Ed25519-ключ передаётся в записи и используется при verify; он не добавляется отдельным полем канонического сообщения.

topo_node_sign_self назначает timestamp строго выше текущего и сохранённого в SQLite,
подписывает ключом instance->my_ed25519_privkey и сохраняет снимок, если БД есть.
При ошибке восстанавливаются timestamp/подпись; другие изменённые вызывающим поля не откатываются.
Поэтому локальные обновления подписывают временный candidate до замены общей записи.

topo_node_verify проверяет диапазон timestamp, node_id=derive(X25519 public_key)
и Ed25519-подпись предоставленным ключом; возвращает 0/-1.
Проверку права участия в группе и допустимости пути выполняет вызывающий BGP-слой.

## NODEINFO wire

Сериализация ручная, без lib/serialize. Packed-заголовок TOPOMSG_NODE содержит поля записи,
group_id/flags, счётчики, hop_count и cumulative_rtt. Далее идут:

| Порядок | Секция |
| --- | --- |
| 1 | node_name_len байт имени без NUL |
| 2 | SOCKMETA4, затем ADDR4 |
| 3 | SOCKMETA6, затем ADDR6 |
| 4 | REALITY с фиксированным полем server_name[256] |
| 5 | SUBNET4, затем SUBNET6, только с TOPO_FLAG_SEND_SUBNETS |
| 6 | hop_count идентификаторов uint64_t |

Числа wire копируются в нативном порядке; IP — сетевые байты. Это представление отличается
от канонического сообщения подписи (timestamp BE, порты LE, строки с NUL).
Счётчики ограничены 255, имя — 63 байтами. dyn_size возвращает размер динамики или -1.

serialize получает ni и nq, оставляет владение у вызывающего и возвращает длину либо -1.
Входные поля должны быть пригодны для публикации; serialize не проверяет подпись.
Hop-list берётся один раз из выбранного живого пути. Radio и phone_status дополняют flags.
Без TOPO_FLAG_SEND_SUBNETS счётчики подсетей равны 0; секции не записываются.

deserialize требует group->instance->topo_groups с пулами и обязательный out_ni.
Остальные out_* независимы и необязательны. Проверяются точная длина, флаг/счётчики,
профили сокетов и IPv4 /0..32, IPv6 /0..128. Все секции обходятся и проверяются независимо
от запрошенных выходов. Подпись и допустимость BGP-пути проверяются отдельно.

Перед разбором переданные выходы обнуляются, прежние объекты не освобождаются.
Успех — 0 и атомарная выдача результата; ошибка — -1 и NULL/0 без частичных объектов.
Пустые секции дают NULL/0. ni уничтожается topo_node_destroy, подсети передаются владельцу
TOPO_GROUP_NODE, hop-list освобождается u_free.

## Локальная публикация

topo_node_init_self создаёт подписанную идентичность с отдельной ссылкой ядра; 0/-1.

topo_group_update_my_nodeinfo готовит local_node из имени, ключей, типа/активности,
radio/phone_status и конфигурационных подсетей. Сравниваются адреса и префиксы,
включая замену подсети при прежнем количестве. CHAT не анонсирует подсети.

Новая запись/подсети готовятся до удаления прежнего local_node. IPv4 проходит route_insert
с запретом пересечений; при конфликте или отказе подготовки/подписи прежние узел и маршруты сохраняются.
Общая подписанная идентичность заменяется после успешного sign_self.
Возврат — число IPv4-подсетей (CHAT: 0), при ошибке -1. Рассылку запускает вызывающий.

topo_node_update_my_addresses отдельно собирает адреса рабочих UDP/TCP-сокетов.
PRIVATE исключаются, UDP probe_only исключаются; LOCAL остаются доступными для локальных подключений.
UDP публикует интерфейс и допустимый наблюдаемый NAT endpoint, IPv6 интерфейс — отдельным списком.
TCP может публиковать внешний IP с port=0, если входящий порт неизвестен.
REALITY-параметры берутся из глобальной конфигурации и связываются с socket_id.

Изменение подписывается/сохраняется до замены списков и рассылается во все группы.
Неизменный набор не переподписывается, но SQL-проекция обновляется повторно.
Возврат 1/0/-1; ошибка проекции может дать -1 уже после применённой подписанной записи.
on_socket_changed инициирует этот пересчёт при событии сокета.

## Пути, RTT и диагностика

best_path выбирает путь с conn->links_up, без close_requested, по минимуму hop_count,
при равенстве — меньшему peer_node_id. READY проверяется отдельно владельцем групповой сессии.
best_hop_list возвращает заимствованный inline-массив; out_count обязателен,
out_rtt необязателен и получает RTT без локального линка. При отсутствии пути — NULL/0.

topo_get_chain_rtt складывает rtt_last локального соединения и cumulative_rtt.
UINT16_MAX обозначает неизвестный путь/локальный RTT либо насыщение суммы.
Единицы RTT и timebase-таймингов связности — 0.1 ms.

ping_request_cbk сообщает, пора ли повторить ping хотя бы в одной группе (TTL 24 часа).
ping_update_rtt обновляет время ping и минимальные RTT проб во всех группах и callbacks, без SQL;
сам по себе не переводит статусы достижимости в REACHABLE.

dump_all пишет group->nodes в BGP/INFO. format_all форматирует ту же очередь в буфер:
реальная длина без NUL, -1 при ошибке форматирования, некорректные аргументы дают 0.
При наличии буфера строка завершена NUL; после первого усечения запись прекращается,
хвост заменяется доступной частью маркера TRUNCATED. Ёмкость ограничена INT_MAX.

Полные объявления и контракты — в topo_node.h; общий жизненный цикл снимка — doc/node_snapshot.md.
