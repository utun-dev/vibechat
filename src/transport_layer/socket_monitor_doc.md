# socket_monitor

Монитор обновляет `ETCP_SOCKET.interface_addr` при изменении интерфейсов и маршрутов ОС.
Он не создаёт сокеты, не выбирает CHAT-пиров и не устанавливает состояние UP транспорта.
Создание/удаление автоматических сокетов выполняет `auto_socket`.

`socket_monitor_init(instance)` требует живые instance/ua и возвращает 0/-1.
Повторная инициализация — ошибка. `auto_sockets=android` делегирует адреса frontend,
на неподдерживаемой ОС init ничего не создаёт. Частичный запуск откатывается.
`socket_monitor_destroy(instance)` допускает NULL и повторное завершение.
Все операции владельца идут в потоке uasync; destroy — вне callbacks монитора, до освобождения ua/instance.

## Адреса и события

`socket_monitor_update_if_addr(es)` не вызывает callbacks. Для netif_index != 0
выбирает IPv4/IPv6 указанного интерфейса, для wildcard bind без индекса — исходный адрес default route.
При явном bind без индекса использует IP local_addr. IPv6 предпочитает стабильный адрес,
затем доступный альтернативный; link-local получает scope ID интерфейса. Порт сохраняется из local_addr.
Каждый пересчёт начинает с пустого результата: исчезновение адреса очищает прежний IP.

Монитор сравнивает прежний и новый interface_addr и вызывает ADDR_CHANGED только при изменении.
Уведомление состояния интерфейса вызывает STATUS_CHANGED и повторную проверку адреса.
Уведомления адресов также пересчитывают wildcard-сокеты; маршруты — сокеты без привязки к интерфейсу.
Обход сохраняет ID и generation до callbacks и повторно находит живой endpoint после STATUS_CHANGED.
Удалённый/заменённый endpoint не получает продолжение старого события; новые сокеты не включаются в текущий снимок.

## Платформы

- Linux: NETLINK_ROUTE с подписками LINK/IPv4+IPv6 IFADDR/ROUTE. Проверяются sender=kernel,
  длины заголовка и полезной нагрузки. EINTR повторяется, EAGAIN завершает чтение.
  ENOBUFS/OVERRUN и усечение дают WARN и полный пересчёт endpoint. Обычные маршрутные события
  пересчитывают wildcard-сокеты только для default route.
- FreeBSD: PF_ROUTE, неблокирующий режим обязателен. Общий четырёхбайтный префикс
  проверяется до обращения к типизированному заголовку. IFINFO, IFANNOUNCE, NEWADDR/DELADDR
  и ADD/DELETE/CHANGE используют соответственно if_msghdr, if_announcemsghdr, ifa_msghdr, rt_msghdr.
  Атрибуты sockaddr не разбираются: актуальные IP берутся из снимка ОС. Неподдерживаемая версия,
  короткий заголовок и ошибочный результат изменения маршрута логируются без изменения сокетов.
- Windows: IP Helper callbacks под critical section накапливают биты событий и счётчики.
  На пачку приходится одна задача `uasync_post_reserved`; только поток uasync обновляет сокеты.
  При OOM постановка логируется, накопленные биты остаются для следующего уведомления.
  Stop запрещает новые задачи, отменяет native подписки с ожиданием callbacks и снимает pending task.
  Если отмена native подписки не удалась, отключённый контекст намеренно сохраняется с ERROR;
  он больше не обращается к instance/ua и не публикует задачи.

При удалении интерфейса/адреса сообщения и старый→новый IP видны в `socket=info`;
ошибки запуска/чтения — warn/error, частные детали — debug.

Определения FreeBSD сверены с [if.h](https://github.com/freebsd/freebsd-src/blob/releng/14.3/sys/net/if.h)
и [route.h](https://github.com/freebsd/freebsd-src/blob/releng/14.3/sys/net/route.h).
