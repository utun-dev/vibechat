# STCP как транспорт ETCP

Нормативный контракт API находится в `stcp_link.h`, переходы физического линка — в `etcp_connections.h`.
Все операции выполняются в uasync-потоке экземпляра ядра.

## Создание и владение

Сервер создаётся через `stcp_server_listen(&cfg, port, on_link, tcp_sock)`.
`cfg` содержит `inst`, `listen_family` (0/AF_INET/AF_INET6) и `reality_enabled`;
ключи, event loop и настройки REALITY берутся из instance. Порт 0 выбирает ОС,
фактическое значение возвращает `stcp_link_server_get_port()`.
После handshake `on_link(link, tcp_sock)` передаёт готовый адаптер владельцу.
Уничтожение слушателя закрывает также принятые им STCP-соединения.

Исходящий адаптер создаёт `stcp_link_connect(etcp_link, remote_addr, port)`.
Родительские `ETCP_CONN` и `UTUN_INSTANCE` уже существуют; ключ пира берётся из
`etcp_link->etcp->crypto_ctx`. Локальный bind задаёт `etcp_link->conn`, NULL означает выбор адреса ОС.
При `port=0` используется порт из `remote_addr`. REALITY и SOCKS выбираются по параметрам линка/instance.
NULL означает отказ запуска без callback. Для возвращённого handle ошибки TCP connect и handshake
также вызывают установленный `on_close`, даже если READY ещё не было.
Callbacks устанавливаются сразу после возврата connect, до следующего poll.

Адаптер хранит заимствованные указатели на физический линк и соединение, а не встроенный `ETCP_CONN`.
Он владеет RX/TX очередями; низкоуровневый `stcp_conn` только заимствует их.
После закрытия raw STCP указатель на него очищается, поскольку серверный conn освобождается автоматически.
Клиентский raw conn принадлежит `stcp_client` до его уничтожения.

## Данные и готовность

`stcp_link_send(link, data, len)` копирует пакет в TX очередь: 0 при успехе, -1 при отказе.
Успех означает постановку в очередь, а не доставку пиру. ETCP передаёт ограниченные размером своей кодограммы пакеты.
RX очередь ограничена порогами STCP; возобновление потребления снимает backpressure чтения TCP.
Обычный RX восстанавливает `ETCP_DGRAM` и вызывает `etcp_packet_decrypted()` с физическим линком;
проверка сессии и дальнейшая доставка выполняются ETCP. Прямой dispatch в `api_bindings` — резервный путь без физического владельца.

STCP READY означает завершённый криптографический handshake, но не завершённое согласование
ETCP-сессии и не READY topo-группы. Клиент сначала вызывает `etcp_link_enter_ready_tcp()`,
затем пользовательский `on_ready`. Если callback перехода закрыл транспорт/соединение,
дальнейшие действия перехода и пользовательский READY прекращаются.
ETCP удерживает соединение на время перехода и после callbacks проверяет, что адаптер всё ещё привязан к тому же линку.

## Закрытие и восстановление

`stcp_link_close()` немедленно запрещает send/RX/READY, отвязывает родительский линк,
снимает обработчики очередей и отключает чтение/запись сокета. Он подавляет `on_close`:
это уведомление предназначено для неожиданного разрыва, а не явной отмены владельцем.
Освобождение очередей, raw STCP/client и самого адаптера выполняется через `call_soon`.
Повторный close внутри активного callback безопасен; после возврата в event loop handle использовать нельзя.

Неожиданный разрыв доставляет `on_close` один раз. Владелец освобождает адаптер через `stcp_link_close()`,
в том числе из самого callback. Серверный ETCP_LINK закрывается; исходящий сохраняется для повторной попытки.
ETCP владеет состоянием физического линка и backoff: 1, 2, 4, 8, 16, затем не более 30 секунд.
Синхронный отказ запуска и асинхронный разрыв используют одну последовательность.
Успешный STCP handshake сбрасывает backoff; повторный запрос при уже поставленном таймере не переносит его срок.
Закрытие ETCP_LINK отменяет повторное подключение. Если обязательный таймер поставить невозможно,
ETCP закрывает соединение с диагностикой вместо сохранения зависшего пути.

`etcp_link_close()` сразу отвязывает физический линк и закрывает его ресурсы. Память сохраняется до выхода
активных внутренних обработчиков (конструктор, RX, INIT/reinit, READY, callbacks и RX-timeout).
Последний обработчик освобождает закрытый объект без дополнительного таймера или выделения памяти.
Callback может закрыть этот линк, соседний линк или всё соединение; повторный close закрываемого линка игнорируется.
Поэтому через callback нельзя сохранять следующий элемент списка и продолжать обход по старому указателю.

Конструкторы ETCP_CONN/ETCP_LINK возвращают NULL, если callback отменил создание.
Конструктор также удерживает память линка: close снимает ресурсы и помечает отмену,
после чего конструктор освобождает своё удержание. Входящий STCP при отказе его присоединения закрывается.
Созданный для него ETCP_CONN удаляется только без других линков и NCD-владельцев:
callback мог уже передать соединение другому сервису или создать запасной путь.
Instance-подписки можно снимать внутри callbacks: запись сразу отключается, освобождение ждёт выхода
из внешней рассылки. Новая подписка не попадает в начатый обход, но доступна вложенному событию.

## Проверки

`test_transport` проверяет передачу, неверный ключ, ранний отказ connect, таймаут handshake,
отмену до первого poll и повторный close из callback.
`test_etcp_transport` проверяет передачу и восстановление после рестарта пира,
закрытие из READY/DOWN для клиента и сервера, plain STCP и REALITY,
отсутствие поздних READY, backoff, его сброс после восстановления и отмену повторного подключения.
Проверяется баланс сокетов, таймеров и учитываемых выделений памяти.
Дополнительно проверяются отмена создания из callbacks и снятие подписки для обеих ролей STCP/REALITY.
Для отмены входящего линка проверяются четыре случая: владелец и другой путь, только владелец,
только другой путь, отсутствие обоих. Используемое соединение сохраняется и доставляет данные в обе стороны,
неиспользуемое удаляется; оба транспорта проверяются с учётом освобождения ресурсов.
`test_etcp_lifecycle` проверяет снятие себя/следующей записи, добавление подписки и вложенную рассылку
для всех четырёх instance-цепочек ETCP.
