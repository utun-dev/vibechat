# Packet Dump (декодирование IP-пакетов)

## 1. Назначение
Вспомогательный модуль для диагностики: парсит сырой IPv4-пакет и формирует человекочитаемую строку с IP-адресами, протоколом, портами, флагами и hex-дампом до 32 байт после IP-заголовка, включая транспортный заголовок. Вызывается из отладочных логов категорий `tun` и `traffic`.

Все чтения ограничены доступной длиной и полем IPv4 total length. Выравнивание входного указателя не требуется: адреса и поля читаются побайтно, независимо от порядка байтов процессора. Динамическая память не выделяется.

## 2. Как пользоваться

```c
#include "packet_dump.h"

// packet_data указывает на начало IPv4-заголовка
const uint8_t* packet_data = ...;
size_t len = ...;

char* str = dump_ip_packet_to_buffer(packet_data, len);
DEBUG_DEBUG(DEBUG_CATEGORY_TUN, "[TUN->] %s", str);
```

**Важно:** функция возвращает указатель на статический буфер (1024 байта). Не thread-safe. Каждый вызов перезаписывает предыдущий результат.

### Примеры вывода

```
IPv4 UDP 192.168.1.2:0 -> 10.20.30.40:443 (28 bytes) len=8 data: 000001bb00080000
IPv4 ICMP 192.168.1.2 -> 10.20.30.40 (28 bytes) echo_request seq=43981 id=4660 data: 080000001234abcd
IPv4 UNKNOWN 192.168.1.2 -> 10.20.30.40 (20 bytes) data:
```

## 3. API

### Функции

**`dump_ip_packet_to_buffer(data, len)`** — парсит IPv4-заголовок и заголовок транспортного уровня, возвращает строку вида `IPv4 PROTO SRC:PORT -> DST:PORT (SIZE bytes) DETAILS data: HEX...`.

Параметры:
- `data` — указатель на начало IPv4-пакета; `NULL` даёт диагностическую строку.
- `len` — число доступных байт; может включать хвост после IPv4 total length, который игнорируется.
- Возвращает общий NUL-терминированный `static char[1024]`; не освобождать и не изменять.
- Размер в штатной строке — IPv4 total length, а не длина захваченного буфера.

Перед разбором проверяются минимальные 20 байт IPv4, version=4, IHL>=20,
наличие всех байт IHL и условие IHL<=total length<=len.
При отказе возвращается только причина с длинами (`Missing IP packet`, `Packet too small`,
`Non-IPv4 packet`, `Invalid IP header length`, `Truncated IP header`,
`Invalid IP total length`, `Truncated IPv4 packet`); она также логируется как `dump=warn`.

Обрабатываемые протоколы:
- **TCP (6):** при наличии 20 байт — порты, seq/ack, флаги (FIN, SYN, RST, PSH, ACK, URG, ECE, CWR), window.
- **UDP (17):** при наличии 8 байт — порты и поле длины UDP.
- **ICMP (1):** при наличии 8 байт — тип/code, для echo_request/echo_reply также seq и id.

Порты выводятся также при значении 0. Все восемь TCP-флагов помещаются целиком;
при отсутствии флагов выводится `none`. Полную корректность транспорта, его длины и checksum модуль не проверяет.

При ненулевом IPv4 fragment offset транспортный заголовок не разбирается;
имя протокола, адреса и hex-фрагмент сохраняются. Для всех фрагментированных пакетов
добавляется `fragment offset=N MF=0/1`, где offset измеряется в байтах.
Первый фрагмент с MF=1 разбирается, если его транспортный заголовок помещается.
При коротком заголовке выводится `partial header: available=N required=M` (`dump=debug`);
для нефрагментированного пакета — `truncated header: available=N required=M` (`dump=warn`).
В обоих случаях доступный hex-фрагмент сохраняется.

Для нераспознанного протокола выводит `UNKNOWN`, адреса без портов и доступный hex-фрагмент.

Hex-дамп: min(32, total length - IHL) байт начиная с `data[ihl]`, включая транспортный заголовок;
группы по 8 байт разделены пробелом. При пустом остатке после `data:` нет hex-цифр.

**`tcp_flags_to_str(flags)`** (static) — преобразует байт TCP-флагов в строку вида `SYN,ACK` или `none`.

### Где используется
- `tun_if.c` — логирование пакетов из/в TUN-интерфейс (категория `tun`, уровень `debug`, общий код платформ)
- `routing_layer/routing.c` — логирование пакетов перед передачей в локальный TUN (категория `traffic`, уровень `debug`)

### Зависимости
- `debug_config.h` — диагностика ошибочного входа и частичного транспортного заголовка (категория `dump`).
- Стандартная библиотека: `<stdio.h>`, `<string.h>`

### Проверки

`make -C tests test_packet_dump` и `./tests/test_packet_dump` вызывают настоящий форматтер:
проверяются вывод TCP/UDP/ICMP/UNKNOWN, все TCP-флаги, нулевые порты, IPv4 options,
77 длин захваченного пакета, невыровненный вход, фрагменты, диагностика неверных заголовков
и сохранность входа. Матрица из 2904 случаев проверяет точный hex для четырёх протоколов,
11 значений IHL и 0..65 байт после IP-заголовка.
