# Dummynet — UDP Network Emulator

## 1. Назначение
Эмулятор сетевых условий: задержка (фиксированная + случайная), сериализация с BWlim и потери пакетов. **FULL** — UDP-прокси между явно заданными endpoints; **INLINE** — фильтр потерь в `send_hook` ETCP_LINK. Задержка и BWlim реализованы в FULL.

## 2. Как пользоваться

### Режим FULL (автономный UDP-прокси)

1. `dummynet_create(ua, bind_ip, listen_port)` — создаёт контекст, открывает UDP-сокет на `listen_port`.
2. `dummynet_set_direction(dn, DUMMYNET_FORWARD, ...)` и `DUMMYNET_BACKWARD` — настраивает параметры для каждого направления.
3. Источник FORWARD — endpoint, заданный как назначение BACKWARD, и наоборот. Порты независимы; `listen_port=0` выбирает ОС.
4. Вызовы выполняются в потоке `ua`; `ua` должен существовать до `dummynet_destroy`. Destroy освобождает только собственные ресурсы.

FULL поддерживает IPv4-литералы и датаграммы **0..1500 байт**. Пустой UDP-пакет передаётся как пакет;
более длинный отбрасывается целиком с WARN, без пересылки усечённого содержимого.
Неизвестный source IP:порт не пересылается и не входит в статистику направлений.

Read callback читает до EAGAIN или до 64 датаграмм за вызов. Ограниченная пачка освобождает
kernel UDP buffer при кратковременном ускорении источника и оставляет время другим событиям.
Один пакет за callback создавал скрытый лимит pps: socket терял пакеты ещё до счётчиков dummynet.
DEBUG `UDP receive batch` показывает размер пачки и исчерпание бюджета.
В Linux-стенде `tools/etcp_lab` (ветка `etcp_lab`) дополнительно снимаются SO_MEMINFO drops/rmem/rcvbuf:
это один общий сокет двух направлений; его счётчики нельзя складывать по направлениям.

Настройка атомарна: ошибка сохраняет прежние параметры и адрес. Endpoints должны различаться,
`dest_ip=0.0.0.0` и нулевой порт запрещены. Сумма fixed+random ограничена 10000 мс, очередь — `INT_MAX` пакетов;
превышение даёт -1. Loss выше 1000 ограничивается до 1000 с WARN.
Смена endpoint разрешена при пустых обоих направлениях. При сохранении endpoint параметры можно менять с трафиком:
delay/loss применяются к новым поступлениям, BW — к следующей сериализации, лимит — к приёму новых пакетов.
Уже запущенный delay и начатая сериализация сохраняют свои сроки; уменьшение лимита не удаляет накопленное.

```
[dest_backward] → [dummynet: loss/queue limit→delay→serializer] → [dest_forward]
[dest_forward]  → [dummynet: loss/queue limit→delay→serializer] → [dest_backward]
```

### Микрофризы Wi-Fi в FULL

Один профиль содержит несколько независимых типов помех, действующих одновременно:

```c
struct dummynet_freeze_spec interference[] = {{10.0, 30}, {0.5, 200}};
dummynet_set_microfreezes(dn, interference, 2, 113);
```

Это в среднем 10 событий/с длительностью 0–30 мс и 0,5 события/с длительностью 0–200 мс.
Частота — не вероятность потери пакета и не фиксированное количество в каждой секунде.
Экспоненциальные интервалы с суммарной частотой и выбор типа пропорционально его частоте
задают суперпозицию независимых пуассоновских источников; длительность равномерная, в целых миллисекундах.
До восьми типов; частота каждого 0,001–1000/с, сумма <=1000/с; максимум длительности 1–10000 мс.
Фактическое начало/окончание обслуживается event loop; округление и опоздание таймера немного снижают частоту.
Это существенно, если средний интервал сравним с миллисекундной точностью таймера.

Помеха общая для обоих направлений. Перекрывающиеся события объединяются, без сложения длительностей.
Delay, приём и ограничение очереди продолжают работать. Сериализация приостанавливается с сохранением
оставшейся работы; после паузы расписание сдвигается на простой. Простой не создаёт кредит для залпа.
При BWlim=0 после паузы передача снова не ограничена по скорости — для проверки шейпера требуется ненулевой BWlim.
HOLD/DROP остаются независимыми режимами направления.

`dummynet_get_freeze_stats(dn, &snapshot)` возвращает счётчики событий по типам, перекрытия,
объединённое время пауз (с текущей), начало/конец текущей паузы и максимальное опоздание таймера.
Сброс статистики направления не меняет эти счётчики. Успешная перенастройка микрофризов сбрасывает их;
`set_microfreezes(dn, NULL, 0, 0)` выключает помехи и завершает паузу.
Ошибка настройки/первого таймера сохраняет старый профиль. Отказ таймера во время работы логируется
и отключает помехи, освобождая передачу. Destroy отменяет таймер помех вместе с остальными ресурсами.
Отдельный PRNG с seed не зависит от числа пакетов, потерь и jitter; реальное расписание зависит также от poll.
События и границы пауз — `debug=debug`, конфигурация и ошибки — категория `etcp`.

### Режим INLINE (send_hook в ETCP_LINK)

1. `dummynet_filter_create(ua)` — создаёт фильтр (нет своего сокета).
2. `dummynet_filter_set_loss(df, permille)` — настройка потерь; 0..1000, превышение ограничивается с WARN.
3. `dummynet_filter_attach(df, link)` — 0/-1, присоединяет к одному живому native UDP-линку того же `ua`.
   TCP/SOCKS5 отклоняются; занятый hook не заменяется. Повтор к своему линку идемпотентен.
4. `dummynet_filter_block_addr/unblock_addr` — 0/-1, IP и порт в **network byte order**, до 4 различных пар.
   Повторное добавление и удаление отсутствующей пары дают 0. Переполнение списка логируется и даёт -1.
5. `dummynet_filter_detach/destroy` снимает только свой hook. Закрытие ETCP_LINK само отвязывает фильтр
   через `send_hook_release`, очищая все поля hook до callback. Фильтр можно уничтожить после линка/ядра
   или присоединить к новому линку. При ручной внешней замене hook сначала следует выполнить detach.

INLINE не создаёт сокетов/таймеров и не эмулирует задержку/BW. Не работавший `filter_set_delay` удалён.
Фильтр не владеет `ua`/линком; заимствованная статистика действительна до destroy фильтра.
SOCKS5 имеет приоритет перед send_hook в общем пути UDP, поэтому attach к нему запрещён.

### Механизмы эмуляции

| Механизм | Реализация |
|----------|-----------|
| **Delay** (fixed + random) | При приёме пакета создаётся uasync-таймер (`dummynet_delay_callback`). После срабатывания пакет кладётся в ll_queue направления |
| **Bandwidth (serializer)** | Срок передачи увеличивается на время сериализации текущего пакета; дробные миллисекунды сохраняются. Один таймер направления выпускает все уже готовые пакеты, без накопления ошибки округления таймера |
| **Loss (permille)** | При приёме: `rand() % 1000 < loss_permille` → дроп. В INLINE-режиме — в хуке отправки |
| **DROP** | `dummynet_set_mode(dn, dir, DUMMYNET_DROP)` теряет новые пакеты и удаляет уже ожидающие, включая delay |
| **HOLD** | Останавливает сериализацию, сохраняя ограниченную очередь. RUN начинает сериализацию головы заново; накопленное выпускается с BWlim |

### Статистика

`recv`/`sent` — число пакетов, `recv_bytes`/`sent_bytes` — UDP-байты без IP/UDP заголовков.
`dropped` — неверный размер/переполнение/ошибка ресурсов или отправки; `lost` — случайные потери и блокировки.
`blocked` — DROP у FULL или блокировка адреса у INLINE; входит в lost.
`queue_size`/`queue_max` учитывают все ожидающие пакеты, включая delay/HOLD. Сброс статистики сохраняет текущий размер очереди.
Дополнительные отладочные счётчики: `delay_timer_set/fire`, `shaper_timer_set/fire`.
FULL учитывает в recv/recv_bytes также целиком прочитанные слишком большие датаграммы и относит их к dropped.
INLINE учитывает все вызовы hook и их байты; блок адреса входит в lost и blocked, ошибка socket_sendto — в dropped.
Пустой пакет увеличивает recv/sent, не увеличивая счётчики байтов. Queue/delay-поля у INLINE всегда нулевые.
Указатели на статистику заимствованы. Необязательные выходы get_debug_counters могут быть NULL;
для неверного контекста/направления запрошенные выходы обнуляются с WARN.

### Ключевые нюансы
- Оба направления нужно настроить до начала трафика; источник проверяется по IP и порту.
- BWlim задаётся в десятичных кбит/с по UDP-байтам; 0 означает unlimited. RTT без очередей — сумма задержек направлений и сериализации.
- Таймеры uasync имеют миллисекундную точность: несколько готовых пакетов могут выйти вместе; средняя скорость сохраняется.
- При достижении `max_queue_pkts` новый пакет отбрасывается. Лимит включает ещё не сработавшие delay-таймеры.
- Все операции — в потоке ua. Destroy отменяет также delay-таймеры, освобождает их аргументы и пакеты.
- Ошибка delay-таймера теряет текущий пакет; ошибка shaper-таймера теряет голову очереди и продолжает обработку остальных.
  Отказы памяти/таймеров/отправки логируются и не завершают процесс. Частичный create откатывает ресурсы.
- INLINE при случайной потере/блокировке возвращает `len`: транспорт считает отправку успешной, фактической отправки нет.
- Потери и jitter используют `rand()`; `srand()` задаёт вызывающий. Случайная задержка может переставить пакеты.
- Категория диагностики — `etcp`. INFO — создание/настройка/режим/уничтожение, DEBUG — пакеты/потери/очередь,
  WARN/ERROR — неверные параметры, переполненные блокировки и ошибки ресурсов/отправки.

## 3. API

### FULL-режим

| Функция | Назначение |
|---------|------------|
| `dummynet_create(ua, bind_ip, listen_port)` | Создать контекст, открыть UDP-сокет, зарегистрировать в uasync |
| `dummynet_destroy(dn)` | Закрыть сокет, отменить таймеры, очистить очереди, освободить память |
| `dummynet_set_direction(dn, dir, delay_fixed_ms, delay_random_ms, bw_kbps, max_q, loss_permille, dest_ip, dest_port)` | Настроить параметры направления |
| `dummynet_set_mode(dn, dir, mode)` | RUN/DROP/HOLD направления, 0 / -1 |
| `dummynet_get_stats(dn, dir)` | Получить статистику направления |
| `dummynet_reset_stats(dn, dir)` | Сбросить статистику (-1 = все направления) |
| `dummynet_get_socket(dn)` | Вернуть fd сокета |
| `dummynet_get_listen_port(dn)` | Вернуть listen_port |
| `dummynet_get_uasync(dn)` | Вернуть указатель на UASYNC |
| `dummynet_get_queue_size(dn, dir)` | Вернуть текущий размер очереди направления |
| `dummynet_get_debug_counters(dn, dir, ...)` | Вернуть отладочные счётчики таймеров |

### INLINE-режим (dummynet_filter)

| Функция | Назначение |
|---------|------------|
| `dummynet_filter_create(ua)` | Создать фильтр |
| `dummynet_filter_set_loss(df, permille)` | Установить вероятность потерь |
| `dummynet_filter_attach(df, link)` | Прикрепить хук к свободному native UDP ETCP_LINK, 0/-1 |
| `dummynet_filter_detach(df)` | Открепить хук |
| `dummynet_filter_destroy(df)` | Уничтожить фильтр |
| `dummynet_filter_get_stats(df)` | Получить статистику |
| `dummynet_filter_block_addr(df, ip, port)` | Заблокировать адрес (до 4 адресов) |
| `dummynet_filter_unblock_addr(df, ip, port)` | Разблокировать адрес |

### Структуры

| Структура | Назначение |
|-----------|------------|
| `dummynet_stats` | Счётчики пакетов/байтов, потерь и размера очереди; точные поля — в dummynet.h |
| `dummynet_dir` | Внутренняя: параметры направления, очередь, таймеры шейпера, отладочные счётчики |
| `dummynet` | Контекст FULL-режима: ua, сокет, два `dummynet_dir`, пул пакетов |
| `dummynet_filter` | Контекст INLINE-режима: ua, loss_permille, link, статистика, список блокировок |

### Зависимости
`u_async.h`, `ll_queue.h`, `memory_pool.h`, `socket_compat.h`, `etcp_connections.h` (для ETCP_LINK), `platform_compat.h`
