# Config Updater (config_updater.c/h)

Модуль обеспечивает согласованные seed Ed25519 устройства и публичный X25519 в INI-файле до его загрузки ядром.
При включённом REALITY также обеспечивает private_key и непустой список short_ids.
При наличии [chatserver] или global.chatserver_enabled обеспечивает постоянный add_key сервера.
Публичный контракт приведён в config_updater.h, общий разбор строк — в config_ini.h.

## Выбор значений

Имена секций сравниваются целиком без учёта регистра, пробелы вокруг имени секции,
ключа и значения удаляются. Имена ключей чувствительны к регистру. Комментарии — #.
Последнее текстовое значение ключа во всех соответствующих секциях определяет результат,
включая пустое или некорректное. Опции из других секций не участвуют.

- `my_private_key` хранит seed Ed25519 в 64 HEX-символах. Публичный Ed25519 должен иметь нулевой бит знака.
- `my_public_key` хранит публичный X25519, восстановленный из seed вызовом `sc_identity_from_seed`.
- Публичный Ed25519 устройства выводится из seed при запуске.
- При отсутствии seed или ошибке формата HEX создаётся новая идентичность. Для правильно записанного seed с неканоническим Ed25519 загрузка завершается ошибкой.
- Сравнение HEX выполняется по байтам: регистр букв не вызывает перезапись.
- При включённом REALITY некорректный/отсутствующий private_key генерируется заново.
  Некорректный/пустой/отсутствующий short_ids заменяется четырьмя случайными ID.
  Корректный список сохраняется целиком. Ошибка одного элемента отклоняет весь список.
- При выключенном REALITY его параметры не исправляются.
- Отсутствующий [chatserver] add_key генерируется через RAND_bytes (32 байта) и сохраняется
  той же атомарной заменой файла. Заданный неверный/нулевой ключ вызывает отказ без изменения файла:
  автоматическая ротация секрета запрещена. Повторный запуск сохраняет корректный ключ побайтно.

HEX проверяется посимвольно до декодирования. Частичные результаты проверки не применяются.
Встроенный NUL и физические строки длиннее 1022 байтов до LF запрещены; CR учитывается в этом пределе.

## Изменение текста

Синтаксически ошибочный ранний дубль поля идентичности или включённого REALITY также исправляется
по выбранному последнему значению: штатный парсер проверяет каждое вхождение.
Корректная итоговая идентичность/REALITY не меняется и не генерируется заново только из-за раннего дубля.
Файл без таких ошибок остаётся побайтно неизменным. Если поле требует исправления,
обновляются все его вхождения в соответствующих секциях. Недостающие поля добавляются
в конец последней подходящей секции, перед её завершающими пустыми строками.
Разделитель перед следующей секцией остаётся после добавленных полей; пробелы и CRLF в нём сохраняются.
Отсутствующая секция создаётся в конце файла.

Посторонние строки сохраняются побайтно. В изменяемых строках сохраняются пробелы,
комментарии и окончания строк вокруг заменяемого значения. Добавляемые строки используют
тип первого окончания строки в файле, либо LF. При необходимости добавляется разделитель
после последней строки без LF. Новый или пустой файл получает [global] с тремя полями идентичности.

Перед записью итоговый текст проверяется строгими декодерами и штатным парсером.
Штатный парсер отклоняет ошибки обработчиков известных опций; при таком отказе исходный файл сохраняется.
Отсутствие необходимости правки идентичности/REALITY не означает проверки остальных настроек:
вызывающая сторона всё равно загружает файл через parse_config.

## Запись и ошибки

config_ensure_keys(filename) принимает непустой путь. Вызывающая сторона
исключает параллельную запись конфигурации. Возврат 0 означает корректные значения и,
если требовалось обновление, успешную запись. Возврат -1 означает ошибку с диагностикой CONFIG.

Новый файл создаётся только при ENOENT. Ошибка доступа, чтения, выделения памяти или
закрытия входного файла прекращает операцию. Временный файл создаётся эксклюзивно
рядом с исходным. Проверяются запись, fflush, синхронизация и fclose до замены имени.

На POSIX применяется rename, затем fsync каталога:
- До успешного rename исходный файл при ошибках сохраняется.
- Ошибка fsync каталога после rename возвращает -1 и логируется с replaced=1.
  Файл уже заменён; устойчивость замены к аварии не подтверждена.
- Сохраняются uid/gid и обычные права доступа (0777); новый файл имеет 0600.
  ACL, xattrs и специальные биты режима не копируются.
- Временный файл удаляется при ошибках до публикации; ошибка удаления логируется.

На Windows используются _commit и ReplaceFileA для существующего файла либо
MoveFileExA с MOVEFILE_WRITE_THROUGH для нового. Модуль не расширяет гарантии
восстановления после ошибок этих Windows API.

Если требуется запись, символические ссылки/reparse points и файлы с несколькими
жёсткими ссылками отклоняются. Проверка исправного файла по ссылке возможна без записи.

Логи показывают причину генерации, изменяемые поля, этап ошибки и факт замены файла.
Значения приватных ключей updater не выводит.

## Вспомогательная функция

bytes_to_hex(bytes, len, hex_str, hex_len) записывает 2*len строчных HEX-символов и NUL.
Буферы не перекрываются. bytes и hex_str обязательны; hex_len задаёт ёмкость результата.
При недостаточной ёмкости или NULL функция обнуляет доступный hex_str[0]; усечения нет.
Проверка ёмкости не вычисляет переполняющееся 2*len+1. При len=0 результат пустой.

## Проверки

tests/test_config_updater.c проверяет сохранение идентичности, регистр, пробелы,
секции и дубли, CRLF, повторный вызов, строгий HEX/списки, длинные строки/NUL, ссылки,
права доступа, ошибки файловых операций и отказы памяти. Внедрение ошибок через
Linux/ELF linker wrappers не добавляет тестовых веток в рабочий код.
tests/test_reality_config.c проверяет базовые сценарии генерации REALITY.
