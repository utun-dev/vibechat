Идентификатор канала (`ch_id`) — публичный Ed25519 группы, 64 строчных HEX-символа.

chatcli — headless chat CLI for uTun
=====================================

TCP JSON-RPC клиент для управления чатом uTun без GUI.

Настройка сервера
-----------------
В конфиге uTun в секции [chatserver] добавить:
    headless_control_bind=127.0.0.1:9999

Протокол
--------
JSON line: запрос {"id":N,"cmd":"...","params"} → ответ {"id":N,"ok":true,"data":...}
При подписке (subscribe) сервер шлёт асинхронные события: {"event":"...",...}
Успешные poll/vote/react обычно возвращают снимок. Если изменение уже сохранено,
но чтение снимка отказало,data содержит ch,message_id,committed:true,snapshot_pending:true.
В этом случае повторяют только feedback <ch_id> <message_id>:повтор poll/react меняет состояние ещё раз.

Переменные окружения
--------------------
CHATCLI_HOST — хост по умолчанию (127.0.0.1)
CHATCLI_PORT — порт по умолчанию (9999)

Команды
-------

dm_start <Ed25519_64hex> [ch_id] [--mode device|groups]
    device: конкретное устройство; groups: обе подгруппы с независимым fallback
    на устройство. Возвращает conv_id, зафиксированный ядром.

dm_file <conv_id> <author_Ed25519_64hex> <seq> <generation> <download|opened>
    download: явно загрузить вложение независимо от автозагрузки.
    opened: подтвердить фактическое открытие пользователем уже проверенного файла.
    Не отправлять opened после одной лишь автозагрузки или подготовки превью.
    author/seq берутся из dm_messages, generation — из dm_list; числа десятичные.

ping
    Проверка соединения и uptime сервера.
    Пример: chatcli ping

status
    Статус узла: NTP синхронизация, активные соединения, NAT.
    Пример: chatcli status

channels
    Список всех каналов с метаданными: id, имя, owner, число мемберов,
    число сообщений, сколько онлайн.
    Уже сохранённый канал с отложенной подготовкой истории виден с msgs=0.
    Пример: chatcli channels

members <ch_id>
    Список участников канала с полным состоянием:
    node_id (полный Ed25519), имя, online, connected, публичные ключи (x25519/ed25519 hex),
    адреса (ip, port, proto, rtt).
    proto: UDP, TCP или TCP+REALITY; deleted-участник показывается offline.
    Строки возвращаются целиком с JSON escaping;ошибка SQL/размера не даёт частичный успешный список.
    Пример: chatcli members 12345

messages <ch_id> [count]
    Последние N сообщений канала (по умолчанию 20):
    id, timestamp, author_id, author_name, content_type, data.
    Пример: chatcli messages 12345 10

send <ch_id> <text>
    Отправить текстовое сообщение в канал.
    Пример: chatcli send 12345 "hello world"

attach <ch_id> <path> [--video]
    Ответ приходит после публикации сообщения в локальной БД;ошибка подготовки/сохранения возвращает ok=false.
    Это не подтверждение доставки пирам. При disconnect подготовка завершается без ответа закрытому клиенту.
    Прикрепить файл к сообщению. Файл копируется в медиа-каталог канала.
    С флагом --video — файл обрабатывается как видео: если ffmpeg доступен,
    перекодируется в H.264/MP4 (720p, ≤2 Мбит); если уже в нужном формате —
    отправляется как есть.
    Пример: chatcli attach 12345 /tmp/photo.jpg
            chatcli attach 12345 /tmp/clip.mov --video

poll <ch_id> <question> <option1> <option2> ... [--multiple] [--custom]
    Создать неизменяемый опрос. По умолчанию разрешён один пункт.
    --multiple разрешает несколько пунктов; --custom разрешает собственный текст.
    Пример: chatcli poll 12345 "Куда пойдём?" "В парк" "В кафе" --multiple --custom
    Ответ содержит message_id; он также виден в команде messages.

vote <ch_id> <message_id> [option_id ...] [--custom <text>]
    Сохранить полный новый ответ. Номера пунктов начинаются с 0, как id в feedback.
    Пустой выбор без собственного текста отменяет голос, сохраняя новый ver.
    При выборе одного пункта свой ответ заменяет готовый пункт; при нескольких дополняет выбор.
    Пример: chatcli vote 12345 <message_id> 0 1 --custom "Ещё один вариант"
            chatcli vote 12345 <message_id>

react <ch_id> <message_id> [emoji_or_id] [--off] [--clear]
    Установить единственную реакцию, заменив предыдущую; --off снимает выбранную, --clear отменяет свою реакцию.
    Пример: chatcli react 12345 <message_id> "👍"
            chatcli react 12345 <message_id> 0 --off
            chatcli react 12345 <message_id> --clear

reactions
    Общий каталог постоянных номеров и эмодзи.

feedback <ch_id> <message_id>
    Текущие реакции, свои состояния, результаты и подписанные ответы участников.
    Для нескольких пунктов проценты считаются от числа ответивших и могут суммарно превышать 100%.
    Отсутствующее исходное сообщение обозначается pending; ответы сохраняются до его получения.

invite <ch_id> [Ed25519_64hex]
    Создать invite-ссылку для канала (формат utun://...).
    Без второго аргумента выбирается лучший достижимый узел.
    Второй аргумент принимает полный Ed25519 из команды invite_nodes.
    CHANNEL-ссылка версии 0x08 содержит ключ приглашения, Ed25519 пригласившего и адреса узла подключения с его X25519.
    Пример: chatcli invite 12345
            chatcli invite 12345 <Ed25519_64hex>

invite_to <ch_id> <Ed25519_64hex> <ip:port> [proto]
    Отправить приглашение конкретному устройству. Адрес устройства — его публичный
    Ed25519 в виде 64 шестнадцатеричных цифр. Транспортный ключ выводится из него.

invite_nodes <ch_id>
    Список достижимых узлов канала, пригодных для invite (включая свой узел).
    Ответ содержит auto_ed25519 и список nodes с полями ed25519 и name.
    Пример: chatcli invite_nodes 12345

server_link
    Получить серверную utun:// ссылку текущего узла с постоянным ключом добавления.
    Требуются включённый chatserver, сохранённый add_key и опубликованные адреса.
    Ссылка секретная; старые серверные ссылки версии 0x03 нужно получить заново.
    Пример на сервере: chatcli server_link

server_add <ch_id> <utun://...>
    Добавить выбранный свой канал на сервер по его серверной ссылке.
    Клиент создаёт обычное приглашение через себя и передаёт его серверу вместе с кодом доступа.
    Сервер проверяет код и выполняет обычный JOIN по установленному соединению.
    Ответ adding=true означает запуск; итог приходит событием connect_result с полным x25519 через listen.
    Повторное добавление не создаёт второй канал. Неверный/сменённый ключ даёт результат -10.
    Пример на клиенте: chatcli server_add 12345 'utun://...'

connect <utun://...>
    Подключиться к каналу по invite-ссылке.
    Декодирует ссылку, сохраняет pubkey и адреса узла в БД,
    запускает процесс подключения.
    Принимает ссылку CHANNEL версии 0x08. Для ссылки SERVER используйте server_add.
    Пример: chatcli connect 'utun://...'

create <name>
    Создать новый канал. Генерирует ключи X25519/Ed25519,
    подписывает join-сообщение.
    Пример: chatcli create "My Group"

listen
    Подписаться на события и слушать в реальном времени.
    Получает: новые сообщения, изменения мемберов, приглашения.
    Выход: Ctrl+C
    Пример: chatcli listen

Настройки хоста/порта
---------------------
    chatcli --host 192.168.1.1 --port 8888 channels
    CHATCLI_HOST=10.0.0.1 CHATCLI_PORT=7777 chatcli status

Описание CHAT-группы:
  rename <ch_id> "Новое имя"           переименовать, сохранив дополнительные поля; ver увеличивается автоматически
  group_info <ch_id>                   прочитать подписанный JSON и token текущей версии
  group_info <ch_id> '{"name":"Имя","ver":2,"options":{"example":true}}'
                                      заменить весь JSON; ver должен быть больше текущего, лимит 1024 байта
Headless JSON: cmd=rename_channel, ch=decimal, name=UTF-8; cmd=group_info, ch=decimal,
description=JSON в строке (необязательно), token=отпечаток прочитанного описания (необязательно).
Изменение требует действующего членства и приватного Ed25519-ключа группы. name — до127 байт UTF-8.
В channels описание хранится в description_json; name вычисляется из JSON и напрямую не изменяется.

Группа устройств (devgroup):
  devgroup status                      своя группа и состояния приглашений
  devgroup rename "Имя"                создать группу либо переименовать свою
  devgroup invite <ch_id> <ed25519>     пригласить устройство по публичному ключу (64 HEX), ответ содержит PIN
  devgroup accept <invite_id>           ввод первого или ответного PIN с другого устройства (без argv)
  devgroup leave                       выйти, удалить локальные ключи и отменить ожидания
Headless JSON: cmd=devgroup_status/rename/invite/accept/leave; параметры name, ch+peer,
invite+pin соответственно. peer — 16 строчных hex-цифр, invite — 32.
status содержит свой показываемый PIN (pin), ожидаемый ввод (input=1/2) и ошибку попытки (pin_error).
Этот снимок предназначен только для локального управления; не публикуйте его и не записывайте в диагностические логи.
Сначала accept на получателе с первым PIN, затем accept на инициаторе с ответным PIN получателя.
Состояния:1 ждёт PIN,2 проверяет,3 передаёт ключи,4 импорт подтверждён,5 отказ,6 истёк,7 результат неизвестен,
8 ждёт ответный PIN,9 проверяет ответный PIN,10 получатель ждёт ключи после проверки второго PIN.
Остановка сервиса отменяет ожидания; сохранённые ключи и квитанции импорта переживают перезапуск.
group_policy <ch_id> <admins|all> [preview_token [keep_id,keep_id,...]]
    Без token: текущий режим, can_edit, Merkle token и список affected для предложенного режима.
    С token: атомарно переподписать выбранные decimal node ID ключом группы и сохранить режим.
    admins — только владелец/администраторы (по умолчанию); all — все действующие участники.
    Только обладатель приватного ключа группы меняет настройку. При conflict получить свежий preview.
    После перехода на admins неподходящие цепочки теряют доступ при следующей завершённой MEMBERS сверке.
    Headless JSON: cmd=group_policy, ch=decimal, all_members=0/1, token=hex (необязательно), keep="[\"decimal\",...]".

Канбан:
  chatcli create "Проект" kanban
  chatcli board <group_id>
  chatcli kanban <group_id> '{"action":"card_create","column":"<column_id>","text":"Задача"}'
  chatcli kanban <group_id> '{"action":"card_move","entity":"<card_id>","column":"<column_id>","before":"<card_id или пусто>"}'
  chatcli kanban <group_id> '{"action":"card_edit","entity":"<card_id>","text":"Правка","parents":["<head_id>"]}'
  chatcli kanban <group_id> '{"action":"card_delete","entity":"<card_id>"}'
  chatcli card_history <group_id> <card_id>
  column_create/rename/move/delete — аналогичные операции колонок, нужен ключ группы.
  parents берутся из снимка открытого редактора. При отсутствии ядро использует текущие heads.

  group_type хранится в подписанном description_json: chat / kanban; отсутствие означает неизвестный тип.
  После принятия тип нельзя изменить или удалить. История сообщений создаётся только для chat.
  Положение карточки выбирается по timestamp операции, при равенстве — по большему unsigned member ID.
  Текст сливается построчно от общего предка; пересечения сохраняют варианты для ручного разрешения.
  Любой действующий участник создаёт, редактирует и перемещает карточки; удалить может автор, модератор или ключ группы.
  При отзыве допуска/модератора ключ группы подписывает срез известных операций прежнего поколения.
  Не попавшие в срез офлайн-операции сохраняются в локальном журнале как inactive и не реплицируются.
  Пока выбранная цепочка среза не получена целиком, показывается прежняя доска без возможности записи.
  Диагностика: [debug] group=debug, kanban=debug, member_sync=info; содержимое карточек в новые логи не выводится.

  card_create/card_edit принимают color (например "#547ddb") из массива colors снимка доски.
  Цвет контура хранится в подписанной истории и синхронизируется. Ширина колонок — локальная настройка GUI.
