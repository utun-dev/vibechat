Windows-инсталлятор VibeChat
===========================

Требования к компьютеру сборки
-----------------------------
Обычные зависимости ChatGUI в MSYS2 UCRT64 (Qt, CMake/Ninja, OpenSSL и т.д.)
и Inno Setup 6.3 или новее: https://jrsoftware.org/isdl.php
Inno Setup нужен только для сборки, пользователю приложения он не требуется.

ISCC.exe ищется в PATH и стандартных каталогах Program Files.
Для нестандартной установки задайте в CMD перед сборкой:
    set "ISCC=D:\Tools\Inno Setup 6\ISCC.exe"

Создание инсталлятора
--------------------
Из корня репозитория:
    tools\chatgui\build.bat    только ChatGUI и его инсталлятор
    build.bat                  ядро, тесты, ChatGUI и его инсталлятор
    build_full.bat             полная сборка и инсталлятор

BAT-скрипты автоматически включают --installer. Отсутствие Inno Setup или
ошибка упаковки завершают сборку с ненулевым кодом, даже при выводе через tee.
Корневые BAT собирают ChatGUI и при отсутствии предыдущего CMakeCache.txt.

Из UCRT64 shell можно запускать вручную:
    cd tools/chatgui
    bash build.sh --installer -j4

Или повторно упаковать уже готовый Windows-комплект:
    cd tools/chatgui
    bash package_win.sh

Результат:
    tools\chatgui\build\installer\VibeChat-<версия>-win64-setup.exe

Версия берётся из project(vibechat VERSION ...) в CMakeLists.txt.
--installer задаёт Release; без этого флага поведение shell-сборки прежнее.
Логи: tools\chatgui\build_win.log, а для корневых BAT также build_win.log
или build_full.log в корне. Итоговый путь печатается после успеха компилятора.

Состав и поведение
------------------
Комплект включает EXE, фактически импортируемые DLL, Qt-плагины Windows/JPEG/WebP
с их зависимостями и лицензии. Проверяются x64 PE-формат и полнота зависимостей.
Конфиги, ключи, базы, медиа, логи, lock-файлы, тесты и старые DLL из build
не включаются. Ошибка компилятора не считается успехом из-за старого setup.exe.

Установка: Windows 10/11 с поддержкой x64, Program Files\VibeChat,
права администратора для установки и настройки firewall. Создаются ярлык
в меню Пуск и необязательный ярлык на рабочем столе; после установки приложение
запускается от исходного пользователя. Входящие подключения разрешаются
правилом "VibeChat (installer)" только для установленного EXE.

На странице дополнительных задач включена по умолчанию опция автозапуска
при входе в Windows для всех пользователей. Ярлык автозагрузки передаёт
--minimized: главное окно запускается свёрнутым, обычные ярлыки открывают его
как раньше. Выбор сохраняется при обновлении; снятие галочки удаляет прежний
ярлык автозагрузки. При удалении приложения этот ярлык также удаляется.

EXE собирается как GUI-приложение: запуск через Проводник, установщик или
автозагрузку не создаёт терминал. Запуск из терминала подключает родительскую
консоль и сохраняет перенаправление stdout/stderr, в том числе в файл или pipe.
Лог приложения показывает режим окна и наличие консоли, лог установки —
выбранный режим автозапуска и путь ярлыка.

Повторный запуск для того же профиля показывает окно уже работающего приложения,
в том числе скрытое в трей или свёрнутое через --minimized. Если открыт мастер
первой настройки или модальный диалог, активируется он. Второе ядро не запускается.
При недоступности работающего экземпляра запрос завершается ошибкой через 5 секунд.
Диагностика активации в логе: GUI instance / GUI activation.

При обновлении установщик предлагает закрыть приложение, использующее EXE/DLL.
Обновление и удаление сохраняют конфиг, ключи, историю и медиа пользователя.
Деинсталлятор удаляет своё правило firewall и установленные файлы программы.
Журналы установки/удаления и вывод netsh сохраняются средствами Inno Setup;
для явного пути журнала используйте /LOG="C:\path\setup.log".

Проверки
--------
На Linux/Unix: python3 tools/chatgui/tests/test_windows_installer.py
Тест запускает настоящие скрипты с подставленными objdump/pacman/ISCC:
проверяет комплект, ошибки, повторную упаковку и GUI-флаг --installer.
Корневой флаг проверяет python3 tests/test_build_script.py build.sh.
Это не заменяет проверку настоящего Inno-компилятора и установщика на Windows.

На чистой Windows без MSYS2/Qt: установка, запуск обычным пользователем,
сообщения/звуки/медиа, обновление с сохранением идентичности, удаление,
повторная установка. Проверить пути с пробелами и имя пользователя с кириллицей.
Проверить автозапуск после входа в Windows, свёрнутость при ранее развёрнутом
окне, восстановление из трея, сохранение выбора и отключение при обновлении.
При запуске из Проводника не должно быть консоли; из терминала проверить
вывод, перенаправление и Ctrl+C. Дочерний процесс камеры также не создаёт консоль.
