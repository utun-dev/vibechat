Пачки Opus в рации
=================

Настройка radio_burst_frames в [chatserver]: 1..10, по умолчанию4.
Desktop: Настройки → Рация → Размер burst-пачки (кадров Opus).
Android: Настройки → Рация → Opus → Размер burst-пачки (кадров Opus).
Значение сохраняется в настройках приложения и фиксируется ядром при следующем
radio_talk_begin — для ручной PTT, VAD, передачи по уровню и headless одинаково.
Изменение только размера пачки не перезапускает захват desktop/Android.

Входной API по-прежнему принимает один Opus-кадр; uasync-контекст группы собирает
до заданного числа кадров. Полная пачка отправляется сразу. При END сначала
уходит неполный хвост DATA, затем отдельный FIN. Повторный BEGIN закрывает прежнюю
передачу с её хвостом и FIN. Отправка после END не переоткрывает передачу.
Если захват остановился без END, хвост уходит не позже target*20мс от первого
кадра (плюс задержка планировщика). Новые кадры не продлевают этот deadline.
Destroy отменяет таймер и логирует отброшенный хвост.

Кадр20мс: при регулярном захвате накопление первой полной пачки добавляет
(N-1)*20мс, то есть60мс для4 и180мс для10. Это не ограничение полной задержки
сети/воспроизведения. Размер не адаптивный: задаётся пользователем.

Wire после ETCP_ID_RADIO:
  group_ed25519:32, src_ed25519:32, stream_id:u16, seq:u16,
  timestamp:u64, flags:u8, hop_count:u8, count:u8, hop_list:32*hop_count,
  затем count записей length:u16 + opus[length] и подпись автора Ed25519 (64 байта).
Порядок байтов чисел хоста, как в прежнем протоколе рации.
Заголовок 79 байт без hop_list. DATA: flags=0, count1..10, length1..512.
FIN: flags=1, count0, без кадров Opus. Остальные flags/хвостовые байты запрещены.
seq — номер первого кадра пачки; следующий кадр увеличивает seq по модулю65536.
FIN использует следующий seq после последнего кадра. Приёмник полностью
проверяет пачку до выдачи первого кадра и изменения кэша дедупликации.
Callback аудио по-прежнему получает отдельные кадры с последовательными seq.
FIN передаётся отдельным callback с opus=NULL/len0.

Промежуточный узел дописывает hop, сохраняя границы пачки и тело. Дедупликация
по (src,stream,seq) работает на уровне пачек; повтор не выдаёт кадры повторно.
Максимальный пакет с16hops: 1+79+16*32+10*(2+512)+64=5796 байта, меньше лимита
кодограммы normalizer в 18 432 байта; фрагментация остаётся в существующем транспорте.
Совместимость со старым форматом отсутствует: обновить отправителей,
получателей и транзитные узлы рации.

radio=info: BEGIN с target/deadline, обычная статистика отправки/завершения.
radio=debug: TX/RX каждой пачки, stream/seq/count/bytes, причина full/end/deadline.
Неверные пакеты, отказ таймера и уничтожение с непереданным хвостом логируются.

Проверки: test_radio_batch (1..10, максимальные кадры, неизменный target внутри
передачи, частичный END, FIN, дубли, повреждённые пакеты, deadline и teardown),
test_radio_mesh (передача пачек по разным путям), test_chat_setting (границы),
test_radio_panel (редактор, сохранение/повторное чтение и отсутствие перезапуска
захвата при изменении только пачки), прежние radio/headless/audio-проверки.
