Исправления
- Activity/peer-sleep подписки удерживают снятые записи до выхода из внешней
  рассылки. Безопасны удаление себя/соседа, вложенное событие и добавление новой
  подписки. Повтор fn+arg не дублируется; более новая эффективная activity
  отменяет остаток старой рассылки. OOM обеих подписок логируется.
- Конструкторы проверяют UASYNC/config/path до побочных действий; общий путь
  создания освобождает частичные ресурсы, сохраняя caller config при отказе.
  Проверяются crypto derivation, запись/close временного файла, создание каталогов
  и индекс сетей. Старый TCP-реестр индексируется по node_id, а не указателю link.
- Выбранный путь общего logger копируется в постоянный буфер; освобождение config
  больше не оставляет заимствованную строку в logger. Уже открытый файловый logger
  сохраняет первый путь при создании/reload другого instance.
- Reload готовит config/firewall/networks до изменения ресурсов. Смена владельцев
  (в том числе db_path, control, TUN/NAT/proxy), подсетей или automatic server-конфига
  пересоздаёт ядро с прежними core/UTUN/chat/running. Повторные имена server также
  выбирают полный путь, сохраняя отдельные секции parser без неоднозначного matching.
- Manual reload сравнивает все server-параметры и IPv6 scope по конфигурации,
  сохраняя неизменённые sockets/ephemeral ports. TCP listener закрывается вместе
  с правильной TCP-моделью; UDP создаётся/удаляется своим API. Устранён лог через
  освобождённое имя. Probe и endpoints других владельцев не удаляются по отсутствию
  server-секции. Конфигурационные clients обновляются также без UTUN; неизменённые
  handles/таймеры сохраняются, копии не ссылаются на освобождённый config.
- Destroy обходит sockets/connections от свежей головы после callbacks,
  освобождает старые TCP queue entries и оставшиеся transport-подписки.
  Повторный destroy/start/reload при разрушении отклоняется; SQLite close ошибки
  видны, BUSY завершается close_v2 до финализации заимствованных SQL-объектов.
- Три headless bind разбираются одинаково: IPv4 literal, полный decimal port
  0..65535. Port=0 выбирает ОС; плохое значение не открывает порт по умолчанию.
  Отказ listener не фатален для чата, частичный контекст очищается.
- Call/radio headless stop освобождает контекст/кодеки, снимает клиентов с UASYNC
  и отменяет cleanup/mix таймеры. Их отказы при старте дают rollback.
- UBSan нашёл невыровненный PCM после 11-байтового headless заголовка и uint64_t
  hop-list в radio_recv. Оба читаются через выровненное хранилище; тест рации также
  использует memcpy вместо int16_t* к невыровненному payload. Wire не менялся.
- Из заголовка удалено объявление несуществующего utun_instance_run; poll принадлежит
  caller. Уточнены владение, состояния, ошибки init/reload, подписки и диагностика.

Контракты и ограничения
Все lifecycle операции выполняются в потоке своего UASYNC, stop/destroy/reload —
вне callbacks останавливаемых модулей. UASYNC принадлежит caller и живёт до конца
очистки. Core start при отказе сохраняет подготовленные ресурсы для retry/destroy;
init при отказе позднего сервиса сохраняет ранее запущенные сервисы.
Create уже выполняет I/O и создаёт listeners/SQLite/router/proxy/monitoring.
Create_from_str требует временного файла /tmp и не является чистым buffer parser.
Logger общий для процесса; его изменения и config updater не входят в транзакцию reload.

Partial reload не атомарен: отказ endpoint сохраняет новый config и отсутствие
endpoint для следующей попытки. Подготовка clients при ошибке сохраняет прежние
самостоятельные handles. Full reload возвращает NULL, если новое ядро не удалось
создать/запустить после уничтожения старого; caller использует возвращённый указатель.
Порядок списков/padding модели может консервативно выбрать restart. IPv6 selector
temporary/permanent меняет адрес в модели при разрешении, поэтому повторный reload
может консервативно пересоздать такой endpoint.
Caller завершает borrowed statements/backups; close_v2 не разрешает использовать
уничтоженный instance. Живые ресурсы в diagnose_leaks сами по себе не доказывают утечку.
Отменённые heap-таймеры UASYNC освобождаются при следующем poll, а pool cache — при
уничтожении UASYNC; тест сверяет active/counters и общий баланс после обоих шагов.
