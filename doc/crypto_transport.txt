Параллельная криптография сетевого транспорта

Конфигурация [global]:
    crypto_tx_threads=4
    crypto_rx_threads=4

Каждое значение независимо, от 0 до 64. 0 оставляет соответствующие I/O и
криптографию в основном uasync. При N > 0 направление создаёт один поток I/O
со своим uasync и N криптоворкеров. По умолчанию: TX I/O + 4 workers и
RX I/O + 4 workers. Настройка применяется при создании ядра, изменения требуют
его перезапуска. Пулы общие для UDP и установившихся TCP этого ядра.

Владение и последовательность

Основной uasync единолично владеет ETCP/STCP, таймерами протокола, маршрутизацией
и callbacks. Фоновые направления не получают ETCP_CONN/ETCP_LINK: только
заимствованный fd, собственные буферы, снимки ключей, адресов и числовые ID.
Все изменения регистраций выполняются в uasync соответствующего направления.
При удалении сокета ядро сначала прекращает I/O и дожидается вычислений,
после этого закрывает fd. Shutdown не запускает вложенный poll основного uasync.

Воркеры выбирают очередное задание из общей FIFO под mutex/condition variable.
Быстрый свободный воркер берёт следующее задание; закрепления соединения за
воркером и отдельных очередей round-robin нет. Это сохраняет простоту и
позволяет параллельно шифровать один насыщенный TCP-поток.

UDP TX:
    ETCP -> копия plaintext/ключа/адреса -> TX I/O -> общий пул AES-CCM
         -> FIFO результатов данного адреса -> sendto -> результат основному uasync
UDP RX:
    RX I/O recvfrom -> копия пакета/ключа + время получения -> общий пул AES-CCM
                   -> FIFO результатов адреса -> обработка ETCP в основном uasync

Неизвестный UDP-пир проходит проверку INIT и вывод ключа в worker. Ключи известных
адресов обновляет только основной uasync управляющей командой в RX I/O.
Уже принятые задания сохраняют свои снимки. Ядро проверяет поколение сокета,
адрес, идентичность ключа и эпоху сессии перед применением результата.
SOCKS5 control/ASSOCIATE остаётся в основном uasync; relay копируется в TX-задание,
UDP-оболочка строится/снимается транспортом. Внешние пакетные драйверы (BLE)
и диагностический send_hook используют прежний путь основного uasync.

TCP TX:
    STCP payload -> TX I/O назначает CTR offset и номера REALITY records
                 -> workers: CTR, затем при REALITY GCM
                 -> FIFO wire-результатов -> send с сохранением partial write
TCP RX:
    recv -> независимые CTR-участки -> workers -> FIFO plaintext -> STCP framing
При REALITY:
    recv -> границы внешних records -> workers GCM -> FIFO проверенных records
         -> назначение CTR offsets -> тот же пул workers CTR -> FIFO plaintext

Фреймирование STCP, CRC-проверка и обработчики протокола работают в основном
uasync. Формат CTR-потока сохранён: worker вычисляет counter по абсолютному
смещению, включая неполные блоки AES. Перестановка результатов workers не
переставляет байты TCP или UDP-пакеты одного адреса.

TCP connect, SOCKS CONNECT и начальные STCP/REALITY handshakes остаются в main.
После выхода из callback чтения готовое соединение передаётся транспортам:
копируются ключи и позиции CTR/GCM, недосланный wire и нерасшифрованные остатки.
Уже расшифрованные два байта длины STCP остаются у его автомата.
При TX=RX=0 и STCP, и UDP сохраняют исходный последовательный путь целиком.

REALITY KeyUpdate допускается только последней записью поколения ключа.
RX не назначает задания следующему поколению, пока эта запись не проверена.
Длина внутреннего plaintext становится известна после GCM authentication и
снятия padding, поэтому CTR RX составляет отдельную параллельную стадию.

Давление очередей и ошибки

Общий кредит направления: 256 задач, до 16 MiB буферов. Он удерживается до
потребления результата основным uasync, включая уже выполненную криптографию.
Дополнительно: UDP 32 задания на адрес, TCP 32 задания / 1 MiB на соединение.
При исчерпании TX кредита пакет не принят (-2); ETCP ждёт пробуждения отправителя.
TCP RX выключает чтение; UDP RX отбрасывает избыточные датаграммы с диагностикой.
Снятие паузы/возврат кредита снова разрешает обработку сохранённых данных.

Успешная постановка в TX считается отправкой для ETCP: отката принятого пакета
нет. Поздняя ошибка UDP возвращает числовой ID попытки; ещё ожидающая ACK попытка
немедленно переводится на повторную отправку. Ошибка TCP закрывает линк и
включает существующий механизм повторной передачи. Мягкое завершение TCP
досылает очередь, затем REALITY close_notify. Немедленное закрытие снимает I/O,
дожидается работников и удаляет все недоставленные callbacks.

Время RX фиксируется непосредственно после recv, до очередей дешифровки.
ETCP использует его для RTT/ACK delay и измерений приёма.

Диагностика: категории socket и crypto (INFO запуск/остановка; DEBUG состояния;
WARN/ERROR отказы). crypto выводит число задач, peak_parallel, суммарное время
ожидания и вычисления при остановке пула. Ключи и plaintext в эти логи не входят.

test_config_parser, test_etcp_transport, test_stcp_traffic.
